# Stock trades (STOCK Act and OGE Form 278-T)

Periodic Transaction Reports filed by members of Congress, shown as filed, side by side with the record. Same rules as [funding.md](funding.md): facts side by side, never cause; neutral wording; the same rules for every member and party.

**The Ethics in Government Act forbids commercial use of these reports.** Trades are free on ThePillory: never behind a paid plan, never in an export, a data feed or an API.

## Sources and loading

`tools/load_trades.py`, run by the **Load stock trades** workflow (`.github/workflows/trades.yml`): daily at 15:23 UTC (after the sync Worker's run, so they don't write to D1 at once), up to 300 new reports (the executive branch's first, then newest first), back to 2023; or by hand in **measure** mode (reads a sample, writes what it found to the run summary, writes nothing) or **load** mode.

| Source | What's read |
|---|---|
| House Clerk (`disclosures-clerk.house.gov`) | the yearly index `<year>FD.zip` (FilingType `P`), then each report's PDF (`public_disc/ptr-pdfs/<year>/<DocID>.pdf`). Electronic reports have a text layer, read with `pdftotext -layout`; scanned paper filings have none and are stored as a link only |
| Senate eFD (`efdsearch.senate.gov`) | the search for Periodic Transaction Reports after accepting the site's terms, then each electronic report's table. Paper filings (`/search/view/paper/…`) are stored as a link only |
| SEC EDGAR | a ticker's CIK (`company_tickers.json`) and SIC code (`data.sec.gov/submissions/CIK….json`); the sector is the SIC division. Cached in `sec_tickers`. `SEC_USER_AGENT` (a name and contact email) is optional but EDGAR asks for one |
| Office of Government Ethics (executive branch) | the President's, Vice President's and Cabinet's **Form 278-T** reports, from the OGE disclosures the sync's executive-funding step lists (`disclosures`, `doc_type` "278 Transaction"). A report with a posted document is read like a House PDF (`parse_oge_ptr_text()`: #, description, type, date, amount; the filer's electronic signature date is the filing date for the 45-day line, and without it no line is shown). One OGE releases only on request (Form 201) is stored with its request link, shown as "Available from OGE on request", never guessed. Already attached to the official, so no name matching. Migration 0025 |
| Scanned 278-T reports | a posted 278-T whose text layer can't be read (a scan; the President's reports are) is queued by the loader in `trade_scans`, with that layer's numbered rows (`text_layer_rows()`, `trade_scan_lines`). The sync Worker's **scanned-trades** step (`workers/sync/src/trades/`, `SCANNED_TRADES_DAILY` 5 reports finished a day; the President's first, newest first, then the rest of the executive branch) reads the PDF from its OGE link twice, with two different models (`SCAN_MODEL_A` claude-sonnet-5-5, `SCAN_MODEL_B` claude-opus-5-5), each told to copy every cell exactly and mark anything hard to read. Each reading asks for rows in chunks (`SCAN_CHUNK_ROWS`, 80 rows: "rows 81 to 160"), until a chunk ends before its last row; the document is cached, so a long report is paid for in full once per model, and every chunk is kept in `trade_scan_chunks`, so a reading resumes in the next round. `checkReadings()` judges **each row on its own**: a row publishes only if it's in both readings under the same number, they agree on its date, type and amount exactly and its description letter for letter, neither marked it hard to read, every value is whole (a full date, a whole range, a form type), and the report's text layer doesn't show a different type for it. Every other row is unread: the member's page shows the report as "[N] of [M] rows transcribed: see the report", with the rows that "couldn't be read with confidence", linked to the scan. The whole report is held for a person (nothing published) only when a reading found nothing, no row agreed, or the text layer shows both readings shifted the rows (most descriptions matching the neighboring row's line better than their own); a text-layer row past the last row read sends the report to a spot check. **Nothing is published by the step**: a report whose rows pass waits on `/admin/review/trades/` ("Waiting for a person"), a link to the report on public pages, until a person compares every row with the scan and confirms it, which publishes the agreed rows labeled "Transcribed by AI from a scanned report · Checked by [name]" (or doesn't publish it); a person can send any held report to be read again. A transcription published before this rule without a person's check is taken back to a link at the start of each run (`holdUnchecked()`). A report that fails to read is tried again on later runs (3 tries, the error shown on the admin page); a failure doesn't count against the daily limit, and an account error (no API credit, a bad key) stops the step for the day. A scan has no filer's signature date, so no 45-day line. Tesseract OCR was tried first and read the tables worse than OGE's own text layer. Migrations 0026, 0027 and 0035 |
| congress-legislators | current committee assignments (`committees-current.json`, `committee-membership-current.json`), matched by Bioguide ID, into `congress_committees` |

Rules in the loader:
- **Only what the report says.** Owner is one of Self, Spouse, Joint, Dependent child; anything else is not stored. Asset names, tickers, types and amount ranges are kept exactly as filed.
- **Matching:** a House report needs exactly one member with the same last name, state and district (`StateDst`); when no member holds that seat under that name (someone who has since moved to the Senate, or to another district after redistricting), exactly one member of Congress from the same state with the same first and last name; a Senate report exactly one senator with the same first and last name. Each load run checks the reports kept unmatched against these rules again and re-reads those that now match one member. No unique match: the report is stored with `official_id` NULL and `unmatched` saying why, and never shown. Measure and load runs list the unmatched filers in the run summary.
- **No guessing:** an electronic report whose table can't be read with confidence (an unknown row, a range without its upper bound) is stored as a link only (`parsed = 0`).

## The Supreme Court

Justices report purchases and sales once a year, in Part VII of the annual report (AO Form 10), not within 45 days. They're read from the reports' text layer (2023 on) by `tools/scotus_trades.py` in the daily Supreme Court refresh, into `data/scotus/trades.json` (not D1), and shown on the justice's Disclosures tab with the same row as everyone else's trades (`tradeRow()`), "Held in" the account the report names. See [scotus.md](scotus.md).

## California: Form 700, Schedule A-1

California's officials file no trade reports; their annual Statement of Economic Interests (Form 700) lists, on Schedule A-1, each investment's fair market value range and, when it was acquired or disposed of during the year, the date. The sync Worker's `executive-funding` step lists each official's Form 700s from the FPPC's search (`disclosures`, source `fppc`): the Governor and statewide officers, the Legislature and Calaveras's supervisors (filed as "Supervisor" with "County of Calaveras" as the agency, `FORM700_COUNTY`). `tools/load_form700.py` (the weekly "Load Form 700 lines" workflow; "measure" writes nothing) reads the newest annual statement for each year since 2023 with `tools/form700.py`: names, descriptions and dates from the text the filer typed (Helvetica, over the Arial form), and the checked boxes by rendering the page and measuring the ink inside each drawn box (checked ≥ 0.25, empty ≤ 0.05; anything between, more than one value box, a partial date or an unusual layout makes the statement a link). Lines go to `form700_lines` and each statement's result to `form700_reads` (migration 0028), never to `trades`: they're shown on the official's More → Disclosures as "Acquired" or "Disposed" with "Value" (the range as filed), and aren't in `/trades/` or its totals. Each line links to the statement through `/api/form700/<index ID>`.

## Tables (migration 0024)

`trade_reports` (one per filed report), `trades` (one per transaction: dates, `days_to_file`, owner, asset, ticker, type, the range as filed with its bounds, SIC and sector), `trade_summary` (per member and year, precomputed after each load: count, total range, open-ended ranges, paper reports), `sec_tickers`, `congress_committees`.

## Pages

- **Executive branch** (the President, Vice President, Cabinet): the same section on their More tab, with their position and agency (as OGE lists them) above the list instead of committees, and "Available from OGE on request" for reports released only on request. `/trades/` has an "Executive branch" choice beside House and Senate.
- **Member page, More tab → Stock trades** (`functions/_lib/trades.js`): a summary first ("[N] trades reported in 2026, totaling $X–$Y in ranges as filed"), current committee assignments as plain facts, then one compact line per trade (newest first, 25 at a time with Load more from `/reps/<slug>/trades/`), then reports filed on paper or not read automatically, each linked. No "conflict" labels or commentary.
- **Quick mode:** one line on the member page, "Reported [N] stock trades this year", opening the list.
- **`/trades/`** (linked from Reps → Browse → Federal and from Laws): the latest trades across Congress, newest first, filtered by chamber, state, sector and member name, 25 at a time. Ordered only by date.
- **Filing timeliness:** when a trade was reported more than 45 days after it happened, its line says "Filed [N] days after the trade". No "late", "violation" or warning colors.
- **Speed:** summaries are precomputed; lists are paged; every query is narrowed by member or capped.
